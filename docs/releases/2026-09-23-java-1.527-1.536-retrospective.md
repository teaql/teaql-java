## Human-readable change and vulnerability statement

The tagged **source** interval `v1.534..v1.535` adds a typed active root to
`UserContext` (`09276dd`). The `v1.535..v1.536` source commit introduces
portable optimistic ID allocation (`9ab328e`). Those are source-history
summaries, **not** verified release notes for the later-uploaded JARs. For
1.527–1.533, no tag fixes a reliable end commit for a per-version change log.
Consequently, a complete compatibility summary for these artifacts cannot be
reconstructed from the evidence collected here.

No contemporaneous dependency-vulnerability scan or accepted-risk record has
been linked to an exact JAR in this range. The recent
[#131](https://github.com/teaql/teaql-java/issues/131) scanner gate covers a
different, newer dependency set and cannot retroactively certify these
versions. Their vulnerability status is **not verified**; Maven resolution
success is not a security finding. Do not label them vulnerability-free or
assign an invented risk owner/date.

## Reproduce the narrow checks

```bash
git ls-remote --tags origin
git verify-tag v1.535-RELEASE  # expected failure: unsigned historical tag
curl -I https://maven.teaql.io/repository/maven-releases/io/teaql/teaql-core/1.536-RELEASE/teaql-core-1.536-RELEASE.jar
mvn -Dmaven.repo.local=/path/to/empty-cache \
  org.apache.maven.plugins:maven-dependency-plugin:3.6.1:get \
  -Dartifact=io.teaql:teaql-runtime:1.536-RELEASE \
  -DremoteRepositories=teaql::default::https://maven.teaql.io/repository/maven-releases/
```

- Link exact-version CI, generated-workspace, and conformance runs where they

- Write version-specific compatibility notes only for changes supported by a
